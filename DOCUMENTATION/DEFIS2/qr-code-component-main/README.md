# Frontend Mentor - Composant QR Code

![Aperçu du design du défi de développement du composant QR Code](./preview.jpg)

## Bienvenue ! 👋

Merci de vous intéresser à ce défi de développement front-end.

Les défis de [Frontend Mentor] permettent d'améliorer vos compétences en développement en réalisant des projets réalistes.

**Pour réaliser ce défi, vous devez avoir une compréhension de base du HTML et du CSS.**

## Le défi

Votre défi consiste à créer ce composant QR Code et à faire en sorte qu'il ressemble le plus fidèlement possible au design fourni.

Vous pouvez utiliser tous les outils que vous souhaitez pour réaliser le défi. Si vous souhaitez pratiquer une technologie ou une technique particulière, n'hésitez donc pas à l'utiliser.

### Besoin d'aide pour le défi ?

[Rejoignez notre communauté] et posez vos questions dans le canal **#help**.

## Où trouver les éléments nécessaires ?

Votre objectif est de réaliser le projet en vous basant sur les designs présents dans le dossier `/design`.

Vous y trouverez une version **mobile** et une version **ordinateur (desktop)** du design.

Les designs sont fournis au format JPG statique. L'utilisation de fichiers JPG signifie que vous devrez faire appel à votre jugement pour déterminer certains styles comme la `font-size`, le `padding` et le `margin`.

Si vous souhaitez disposer du fichier de design Figma afin de vous familiariser avec des outils professionnels et réaliser plus rapidement des projets plus précis, vous pouvez [s'abonner en tant que membre PRO].

Tous les éléments nécessaires au projet se trouvent dans le dossier `/images`. Les ressources sont déjà optimisées.

Vous trouverez également un fichier `style-guide.md` contenant les informations dont vous aurez besoin, notamment :

* la palette de couleurs ;
* les polices utilisées ;
* ainsi que les autres informations nécessaires au développement du projet.

## Utilisation des assistants de programmation IA

Nous avons inclus deux fichiers pour vous aider si vous utilisez des assistants de programmation basés sur l'IA (comme Claude, GitHub Copilot, Cursor, etc.) pendant la réalisation de ce défi :

* `AGENTS.md` — Contient des instructions détaillées destinées aux assistants IA afin de les guider dans leur aide pendant la réalisation du défi. Ces instructions sont adaptées au niveau de difficulté du défi. L'IA fournira ainsi une aide correspondant à votre niveau d'apprentissage : davantage d'accompagnement pour les défis débutants et davantage d'autonomie pour les défis avancés.

* `CLAUDE.md` — Un fichier de redirection qui indique aux outils utilisant Claude de se référer aux instructions présentes dans `AGENTS.md`.

### Comment les utiliser ?

Vous n'avez rien de particulier à faire !

Ces fichiers sont automatiquement détectés par la plupart des outils de programmation utilisant l'IA. L'IA lira les instructions et adaptera son comportement afin de devenir un meilleur partenaire d'apprentissage, en vous guidant vers les solutions plutôt qu'en vous donnant directement les réponses.

**Remarque :**

Ces fichiers sont conçus pour vous aider à **apprendre**, et non pour faire le travail à votre place.

L'IA est donc invitée à poser des questions, donner des indications et expliquer les concepts plutôt qu'à écrire des solutions complètes.

## Réalisation de votre projet

Vous êtes libre d'utiliser la méthode de travail qui vous convient.

Voici cependant un processus recommandé. Vous n'êtes pas obligé de suivre toutes ces étapes :

### 1. Créer votre projet

Initialisez votre projet en tant que dépôt public sur [GitHub].

La création d'un dépôt facilitera le partage de votre code avec la communauté si vous avez besoin d'aide.

Si vous ne savez pas comment faire, vous pouvez consulter la ressource [Try Git].

### 2. Publier votre projet

Configurez votre dépôt afin de publier votre code à une adresse web.

Cela sera également utile si vous avez besoin d'aide pendant le défi, car vous pourrez partager l'URL de votre projet en complément de l'URL de votre dépôt.

Il existe plusieurs façons de publier votre projet et nous proposons plusieurs recommandations ci-dessous.

### 3. Analyser les designs

Examinez les différents designs afin de commencer à planifier la manière dont vous allez réaliser le projet.

Cette étape est importante car elle vous permet d'anticiper votre travail et de réfléchir aux classes CSS à créer ainsi qu'aux styles réutilisables.

### 4. Créer la structure HTML

Avant d'ajouter les styles, structurez votre contenu avec du HTML.

Commencer par écrire le HTML permet de se concentrer sur la création d'une structure de contenu propre et correctement organisée.

### 5. Ajouter les styles de base

Commencez par définir les styles principaux de votre projet, notamment les styles généraux du contenu comme :

* `font-family`
* `font-size`

### 6. Construire progressivement la page

Commencez à ajouter les styles en partant du haut de la page et progressez vers le bas.

Ne passez à la section suivante qu'une fois que vous êtes satisfait du résultat de la section sur laquelle vous travaillez.

## Déployer votre projet

Comme indiqué précédemment, il existe de nombreuses façons d'héberger gratuitement votre projet.

Les hébergeurs que nous recommandons sont :

* [GitHub Pages]
* [Vercel]
* [Netlify]

Vous pouvez héberger votre site avec l'une de ces solutions ou avec l'un des autres fournisseurs de confiance que nous recommandons.

Vous pouvez consulter notre [guide des hébergeurs recommandés et de confiance] pour obtenir davantage d'informations.

## Créer un fichier `README.md` personnalisé

Nous vous recommandons fortement de remplacer ce fichier `README.md` par un README personnalisé.

Nous avons fourni un modèle dans le fichier [`README-template.md`] présent dans le code de départ du projet.

Ce modèle vous indique les informations que vous pouvez ajouter à votre README.

Un README personnalisé vous permettra notamment :

* d'expliquer votre projet ;
* de présenter votre réalisation ;
* de décrire votre méthode de travail ;
* de réfléchir à ce que vous avez appris pendant le projet.

Vous êtes libre de modifier notre modèle autant que vous le souhaitez.

Une fois vos informations ajoutées au modèle, supprimez ce fichier et renommez `README-template.md` en `README.md`.

Cela permettra à GitHub d'utiliser votre fichier comme README
